# 音频导入后连续 Qt 断言与崩溃

## 现场证据

2026-10-17 两次 Debug 会话均呈现相同顺序：

- `build/Debug/logs/CatchEditor_2026-10-17_00-23-37.log`：00:24:05.613 新谱面保存完成，00:24:05.631 起连续报 `qnumeric.h:516`。
- `build/Debug/logs/CatchEditor_2026-10-17_00-25-06.log`：00:25:25.538 新谱面保存完成，00:25:25.553 起连续报同一断言。
- 断言为 `ASSERT: "value < maximalPlusOne"`，对应 Qt 6.10.2 的浮点到整数转换上界检查。
- 本机第二次导入的 `JAZZOR C/1792167921.ogg` 是完整的 156.60 秒、48 kHz 双声道 Vorbis 文件，已成功转换。

新建流程只有转换成功才会创建 `.mc` 并开始自动测时。因此现场保存后的错误发生在自动测时阶段。保存时的 `Audio source path not available` 日志来自默认 Chart 尚未绑定源路径，不是本次断言的来源。

Windows 同时留下了两份进程转储，事件中的异常为 `0xc000041d`；仅凭系统记载的 msvcrt/TextShaping 故障模块无法定位首个错误。本次通过实际异步调用复现了更早的 Qt 断言，无需以末端系统模块推测根因。

## 根因与提交追踪

`MainWindow::newChart()` 以 `double(INT_MAX) * 1000` 毫秒请求分析整首音乐。
`BpmDetector::decodeMonoRange()` 原先这样换算结尾：

```cpp
static_cast<qint64>(qCeil((startMs + durationMs) * sampleRate / 1000.0))
```

Qt 的 `qCeil()` 和 `qFloor()` 返回 **int**。外层转成 `qint64` 无法避免内层先发生的 32 位整数溢出。
48 kHz 时，整曲请求得到 `103079215056000` 帧，远超 `2147483647`。该换算原本在每个解码数据块中执行，导致重复触发相同断言。

提交 `fb3d717`（2026-05-29）最初加入上述换算，但当时检测时长最多 120 秒。
提交 `d34b25a`（2026-09-25，`feat: apply phase-aware BPM measurements`）移除了 120 秒限制，并将新建谱面参数改为整曲时长；原来的 32 位中间结果因此成为确定性错误。
`645fd70` 移动/扩展了相关代码，当前 blame 会指向它，但溢出的组合更早就已存在。

该问题也会影响不需要转换的 OGG 新建流程；音频格式并不是触发条件。Release 不启用同样的断言检查，仍可能得到错误的裁切边界或测时失败。

## 修复

- 使用 `std::floor/std::ceil` 保留浮点结果，通过有限值和 64 位范围检查后再直接转换为 `qint64`。
- 上界采用严格小于 `2^63`，避免 `double(qint64::max())` 向上舍入造成边界误判。
- 首个有效音频格式到达时只计算一次区间；不再为每个数据块重复计算。
- 无法表示的请求通过正常解码失败路径返回错误，停止后续处理。
- 新建流程新增转换成功、开始测时及测时失败原因日志。
- 保留整曲分析、原有裁切规则和内存限制，没有恢复 120 秒截断，也没有通过隐藏断言处理问题。

## 验证

新增 `BpmDetectorFileTests`：

- 真实异步 WAV → Vorbis 转换后，以新建谱面的原参数调用异步检测，并与正常有限时长的 BPM/offset 结果比较。
- 8 / 44.1 / 48 / 96 kHz 整曲请求。
- 含小数毫秒的裁切采样边界。
- 极大起点、极大时长、起止相加溢出、恰好到达 `2^63` 帧的错误返回。
- 可选只读本机导入音乐验证。

修复前同一异步流程在成功生成 OGG 后立即复现 `qnumeric.h:516`。为避免自动化运行弹出原生断言窗口，首次诊断运行的临时消息处理器记录首个 fatal 后以 86 退出；该处理器未保留在最终测试中。

修复后的 Debug 和 Release 运行均通过新增回归，包括本机 `JAZZOR C/1792167921.ogg`，测得 BPM 70.5；Debug 明细为 13 项检查通过。
读取前后音频 SHA-256 均为 `10E96450A5325393435C41A8FAAE8B0C4B05C864E70F5D44480747E0831A5D2E`。
自动生成的转换文件和测试 WAV 均放在临时目录，没有修改用户谱面。

本机验证产物位于忽略的 `artifacts/audio_import_*`。完整菜单交互没有自动驱动；测试覆盖了其中真实的转换、进度对话框、异步回调与自动测时链路。
